## 1. CyberSec Evidence Board (`app2.py`)

The primary web interface for auditing prompt injection attacks and evaluating the upstream StruQ Filter Node defense.

### Launching the Dashboard

```bash
streamlit run demo/app2.py
```

### Key Sections:

1. **📊 Attack & Defense Benchmark Dashboard**:
   - Visualizes live and archived benchmark metrics from [`results/struq_attack_and_defense_results/`](file:///home/user/Desktop/Data/Code/Attk_Def_CyberSec_in_LLMs/results/struq_attack_and_defense_results/).
   - **Metrics Tracked**:
     - Baseline vs. Defended Clean Accuracy ($Acc_{clean}$).
     - Attack Success Rate ($ASR$) per variant (V0–V4) and per attack method.
     - ASR Reduction ($\Delta ASR$) and Defense Efficacy Badges (🛡️ *Neutralized*, ✅ *Mitigated*, ⚠️ *Partially Vulnerable*).
     - Front-end telemetry: Delimiters neutralized, chunks processed, and cache hit rates.
   - Interactive Plotly bar charts and drilldown tables.

2. **🧪 Interactive Attack & Defense Playground**:
   - Allows researchers to select any question from the 1,273 MedQA test set or compose a custom clinical question and choices.
   - **Attack Selection**: Pick from 11 attacks (`naive`, `escape_deletion`, `fake_completion`, `completion_real`, `combined`, etc.).
   - **Target Answer**: Choose the adversary's desired forced answer (e.g., force answer `C` when correct answer is `A`).
   - **Comparative Execution**: Runs both the **Undefended Baseline** and **Defended Pipeline (StruQ Filter Node)** side-by-side, displaying outputs and defense outcomes in real time.

3. **🔍 Forensic Attack & Defense Inspector**:
   - Step-by-step forensic trace of the adversarial lifecycle:
     - **Raw Injected Text**: Visualizes where the payload was placed.
     - **Front-End Filter Output**: Shows tokens removed by `recursive_filter()`.
     - **Overlapping Chunking**: Inspects sliding-window boundaries.
     - **StruQ Model Sanitation**: Displays the prompt and completion from `Mistral-7B-v0.1-StruQ`.
     - **Multi-Agent Execution**: Complete agent traces (Planner plan, Examiner option analysis, and Evaluator feedback).

4. **📁 Clean MedQA Benchmark Baseline**:
   - Historical preservation of unattacked ablation benchmarks (V0–V4) with error case analysis and confusion matrices.

## 2. Clinical Ablation Dashboard (`app.py`)

The companion dashboard focused purely on clinical diagnostic reasoning and ablation analysis:

```bash
streamlit run demo/app.py
```

- **Ablation Comparison**: Side-by-side accuracy comparisons across V0 (Direct LLM), V1 (RAG-only), V2 (Multi-agent no memory), V3 (Full system), and V4 (No evaluator).
- **Two-Step Retrieval Inspector**: Inspects intermediate clinical keywords generated by the LLM before ChromaDB querying.
- **Trace Explorer**: Visualizes multi-agent negotiation logs.

## 🛠️ Backend Architecture

- **`runner_struq.py`**:
  - `run_live_struq_trial(...)`: Executes a single question under attack with and without the StruQ Filter Node.
  - `parse_struq_benchmark_log(...)`: Resilient regex parser that extracts cumulative progress and metrics from ongoing benchmark runs.
  - `load_struq_attack_and_defense_data(...)`: Aggregates summary JSON, markdown reports, and log files into a unified dashboard data structure.
- **`attack_data.py`**:
  - `ATTACK_CATALOG`: Standardized metadata, descriptions, and formulas for all 11 prompt injection attacks.
  - `build_asr_comparison_dataframe(...)`: Formats benchmark metrics into Pandas dataframes for Plotly rendering.
